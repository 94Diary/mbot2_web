# สิ่งที่ตกลงกันแล้ว

รวมทุกการตัดสินใจจากการคุยออกแบบ เรียงตามหัวข้อ ถ้าจะเปลี่ยนข้อไหน ให้แก้ไฟล์นี้ก่อนแล้วค่อยแก้โค้ด

## 1. ภาพรวมและกลุ่มผู้ใช้

- เว็บมี 2 หน้าที่: **สอน** เรื่อง mBot2 ตั้งแต่ติดตั้งจนหุ่นวิ่ง และ **เชื่อมต่อ ดู สั่งงาน** หุ่น
- กลุ่มหลักคือรุ่นน้องที่จะรับช่วงโปรเจกต์ต่อ แต่เว็บ **เปิดสาธารณะ** ใครก็ใช้ได้
- โค้ดหุ่นและซิม **รันบนเครื่องของผู้ใช้แต่ละคน** เว็บไม่รันซิมแทน
- จำนวนหุ่นไม่ตายตัว แสดงตามที่เชื่อมได้จริง

## 2. การเชื่อมเว็บกับเครื่อง

- ใช้ **ตัวเชื่อมเครื่อง (agent)** เขียนด้วย Python ติดตั้งใน WSL ครั้งเดียว (รายละเอียด: agent.md)
- เบราว์เซอร์สั่ง Ubuntu เองไม่ได้ จึงเลี่ยงการติดตั้งไม่ได้ ผู้ใช้ต้องพิมพ์คำสั่งติดตั้ง 1 บรรทัด หลังจากนั้นไม่ต้องเปิด Terminal อีก
- **ไม่ต้องเชื่อม VS Code** VS Code เป็นแค่ที่แก้ไฟล์ ตัวเชื่อมอ่านโค้ดจาก `~/ros2_ws` โดยตรง
- ตัวเชื่อมรัน **เฉพาะคำสั่งที่กำหนดไว้** ห้ามมีช่องพิมพ์คำสั่งอิสระบนเว็บ
- เว็บต้องเป็น HTTPS เพราะ Chrome 142+ / 147+ ขออนุญาตผู้ใช้ก่อนให้เว็บสาธารณะต่อเข้า localhost (Local Network Access)
- รอบแรกสั่งได้เฉพาะ **เครื่องที่เปิดเว็บอยู่** ไม่สั่งข้ามอินเทอร์เน็ต

## 3. ขั้นตอนใช้งานหุ่น

- **ซิม:** เลือกจำนวนหุ่น + โลก → กด **รันซิม** → ความคืบหน้า build → Gazebo → rosbridge → เชื่อมเว็บ → **เด้งไปหน้าควบคุมเอง** หุ่นเริ่มวิ่งทันที
  - ไม่มีหน้า “วางหุ่น” และไม่มีรายการ “หุ่นที่เจอ” สำหรับซิม
  - มีสวิตช์ “Build ใหม่ก่อนรัน” และ “ซ่อนหน้าต่าง Gazebo (headless)”
  - Build ล้มเหลว → บอกไฟล์และบรรทัดที่ผิด + กล่องข้อความจาก Terminal + ปุ่มรันอีกครั้ง
- **หุ่นจริง:** ค้นหาหุ่นใน Wi-Fi วงเดียวกัน → หน้าวางหุ่น (**แค่ข้อความเตือน ไม่มีช่องติ๊ก**) → ควบคุม → กดเริ่มสำรวจ
- ถ้ามีภารกิจค้างอยู่ เข้าคอนโซลแล้วไปหน้าควบคุมเลย จนกว่าจะจบหรือบันทึก

## 4. หน้าควบคุม

- **เลือกหุ่นจุดเดียว:** การ์ดหุ่นแถวบน (ทุกตัว / หุ่นแต่ละตัว) คุม **ทั้งแผนที่และ log พร้อมกัน** ไม่มีตัวกรองแยก
- แต่ละการ์ดหุ่นมี: ชื่อ สถานะ แบต (แสดงตลอด) โหมดสำรวจ/ตัดทาง ปุ่มแก้ชื่อและสี
- **แก้ชื่อและสีหุ่น** เปลี่ยนเฉพาะบนเว็บ namespace ใน ROS (`/mbot1`) ไม่เปลี่ยน มีเตือนเมื่อสีซ้ำ
- **ทางแยก** ที่หุ่นมาร์กแสดงเป็นจุด **ทางตัน** เป็นกากบาท (Duck ชอบแบบนี้ ห้ามเอาออก)
- สีเส้นบนแผนที่ = **หุ่นตัวแรกที่ผ่าน** เส้นนั้น มีเข็มทิศ
- การแสดงแผนที่ 3 แบบ: **เส้นที่หุ่นลาก** (ค่าเริ่มต้น) / **แผนที่เต็ม + เส้นหุ่น** / **แผนที่เต็ม** สองแบบหลังใช้ได้เมื่อใส่แผนที่อ้างอิง
- ปุ่ม **หยุดทุกตัว** อยู่ในแถบเมนูล่างตลอดเวลา

## 5. แผนที่

- แยกเป็น 2 เรื่อง:
  - **โลกในซิม (.sdf):** กำหนดกำแพงที่หุ่นสำรวจ อัปโหลดเพิ่มได้ ไฟล์ลงโฟลเดอร์ worlds ในเครื่องผู้ใช้ผ่านตัวเชื่อม
  - **แผนที่อ้างอิง:** ใส่ไว้ดูบนเว็บ (กรณีศึกษา) **ไม่ใช่ฟีเจอร์หลัก** เพราะจุดประสงค์หลักคือการสำรวจ
- แผนที่อ้างอิงรับ `.json` (ฟอร์แมตของเว็บเอง) และ `.sdf` (แปลงกำแพงเป็นภาพมุมบน) **ไม่รับรูปภาพ** ในรอบแรก เพราะต้องตั้งสเกลเอง
- แผนที่ที่บันทึกอยู่ **ในประวัติแต่ละรอบ** และเลือกมาใช้ซ้ำได้

## 6. ประวัติ

- log ของหุ่นและแผนที่อยู่ **ในประวัติแต่ละรอบ** (แท็บ สรุป / แผนที่ / Log)
- ประวัติเป็นของแต่ละผู้ใช้ เห็นเฉพาะของตัวเอง
- **หน้าประวัติเป็นรายการยาวลงมาอย่างเดียว** ไม่ต้องมีส่วนโชว์พิเศษ (ไม่มีตัวเลขสรุป ไม่มีการ์ดรอบล่าสุด)
  - จัดกลุ่มตามวัน มีค้นหา กรองผล กรองโลก เรียงลำดับ
- ทุกรายการที่ยาวเกิน 10: เลือกแสดง **10 / 20 / 30 / 50 ต่อหน้า** และมีปุ่มเปลี่ยนหน้า
- แต่ละรอบเก็บ **สภาพแวดล้อม** ด้วย: โลก, commit ของโค้ดหุ่น, เวอร์ชันตัวเชื่อม, ค่าตั้งที่ใช้
- **ประวัติการกระทำบนเว็บ (Audit log)** แยกจากประวัติภารกิจ อยู่ในหลังบ้าน

## 7. บทบาท

- 3 บทบาท: **ผู้เยี่ยมชม / สมาชิก / ผู้ดูแล** + ป้าย **เจ้าของระบบ** สำหรับผู้ดูแล 1–2 คน (รายละเอียด: roles-permissions.md)
- ผู้เยี่ยมชม **รันซิมในเครื่องตัวเองได้** แต่บันทึกขึ้นเว็บไม่ได้ (ดาวน์โหลด .zip เก็บเองได้)
- ไม่มีการดูภารกิจสดของคนอื่น
- สลับ “ใช้งานหุ่น / หลังบ้าน” ได้เฉพาะผู้ดูแล
- หลังบ้าน = **web dashboard** สำหรับจัดการเว็บ ไม่ใช่ที่คุมหุ่น

## 8. หน้าตาและการใช้งาน

- อ้างอิงอารมณ์ SpaceX Crew Dragon console / NASA mission control แต่ต้องใช้ง่าย ไม่เอาโทน navy/ดำทึบแบบ dashboard ทั่วไป
- สีหลัก: ขาว ส้ม ฟ้า ดำ · มีโหมดสว่าง/มืด
- ฟอนต์ Prompt (หัวข้อ) + IBM Plex Sans Thai (เนื้อหา) + IBM Plex Mono (ตัวเลข/โค้ด)
- ความโค้ง 22 / 16 / 12 / pill · ปุ่มแบบพลาสติกมีเงากด · เส้นปลายมน
- ไม่เอาแผ่นรูพรุนเป็นพื้นหลังหน้าแรก (Duck บอกไม่สวย)
- หน้าแรก: แนะนำหุ่น + ตอบ 3 คำถาม (mBot2 คืออะไร / เว็บนี้ทำอะไร / เริ่มยังไง) มีโมเดลหุ่นด้านขวา
- **ไม่ยัดทุกอย่างในหน้าเดียว** แยกหน้าตามงาน
- **แถบเมนูคอนโซลล็อกติดขอบล่างเสมอ** บนมือถือเป็นแท็บแบบแอป
- ภาษาไทยทั้งเว็บ ข้อความสั้น บอกวิธีแก้เมื่อผิดพลาด

## 9. ความปลอดภัยและกฎหมาย

- HTTPS, 2FA บังคับสำหรับผู้ดูแล, ล็อกบัญชีเมื่อผิด 5 ครั้ง, CAPTCHA หลังผิด 3 ครั้ง
- ลืมรหัสผ่านตอบข้อความเดียวกันเสมอ ลิงก์ใช้ได้ 30 นาทีครั้งเดียว
- แบนเนอร์คุกกี้ตาม PDPA: ยอมรับ/ปฏิเสธเด่นเท่ากัน เลือกรายหมวดได้ ถอนได้ง่าย
- สำรองข้อมูลตามกฎ 3-2-1-1-0 และทดสอบกู้คืนทุก 3 เดือน
- เช็กสิทธิ์ที่ API ทุกครั้ง การซ่อนปุ่มไม่ใช่ความปลอดภัย
