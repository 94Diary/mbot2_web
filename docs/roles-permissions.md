# บทบาทและสิทธิ์

## บทบาท

| บทบาท | ใคร | สรุป |
|---|---|---|
| **ผู้เยี่ยมชม** (guest) | ไม่ได้เข้าสู่ระบบ | อ่านบทเรียน · รันซิมในเครื่องตัวเองได้ แต่บันทึกขึ้นเว็บไม่ได้ |
| **สมาชิก** (member) | สมัครแล้ว ยืนยันอีเมลแล้ว | ใช้หุ่นครบ บันทึกภารกิจ เห็นประวัติของตัวเอง |
| **ผู้ดูแล** (admin) | ทีมที่ดูแลเว็บ | เข้าหลังบ้าน จัดการเนื้อหา สมาชิก ข้อมูล ตั้งค่าเว็บ |
| **ผู้ดูแล + เจ้าของ** (owner) | 1–2 คน | ผู้ดูแลที่ทำเรื่องย้อนกลับยากได้ |

ในฐานข้อมูลเก็บ `role ∈ {member, admin}` และ `is_owner: boolean` (owner ต้องเป็น admin เสมอ)
ผู้เยี่ยมชมไม่มีแถวในตาราง users

## กฎ

1. **ต้องมีเจ้าของอย่างน้อย 1 คนเสมอ** (แนะนำ 2) เจ้าของคนสุดท้ายถอดตัวเองหรือถูกลดสิทธิ์ไม่ได้ → API ตอบ `409 LAST_OWNER`
2. ผู้ดูแลจัดการได้ **เฉพาะบัญชีสมาชิก** เปิดดูบัญชีผู้ดูแลคนอื่นได้แต่ปุ่มจัดการไม่ขึ้น
3. ไม่มีใครแก้บทบาทหรือระงับ **ตัวเอง** ได้
4. ผู้ดูแลและเจ้าของ **ต้องเปิด 2FA** ถ้ายังไม่เปิด เข้าหลังบ้านไม่ได้ (บังคับไปหน้าตั้ง 2FA)
5. **Audit log** ไม่มีใครลบหรือแก้ได้ รวมถึงเจ้าของ
6. สมาชิกที่ **ยังไม่ยืนยันอีเมล** ใช้คอนโซลได้แบบผู้เยี่ยมชม (บันทึกไม่ได้)
7. สมาชิกที่ **ถูกระงับ/แบน** เข้าบัญชีไม่ได้ เห็นหน้าระงับพร้อมเหตุผล วันหมด และปุ่มอุทธรณ์ ส่วนคอนโซลในเครื่องตัวเองยังใช้ได้แบบผู้เยี่ยมชม *(ตัดสินใจแล้ว — ถ้าต้องการล็อกคอนโซลด้วย ให้แก้ข้อนี้)*
8. สลับมุมมอง “ใช้งานหุ่น / หลังบ้าน” แสดงเฉพาะผู้ดูแล

## การบังคับใช้

- **API เช็กสิทธิ์ทุก endpoint** ไม่มีสิทธิ์ตอบ `403` การซ่อนปุ่มใน UI ไม่นับเป็นความปลอดภัย
- UI ใช้ฟังก์ชันเดียว `can(permissionKey)` ซ่อนหรือปิดปุ่ม และแสดงป้าย “ดูอย่างเดียว” เมื่อเห็นข้อมูลแต่แก้ไม่ได้
- เข้าหน้าหลังบ้านที่ไม่มีสิทธิ์ → หน้า 403 พร้อมปุ่ม “ไปหน้าที่เข้าได้”
- ทุกการเปลี่ยนบทบาท ระงับ แบน ลบ → Audit log พร้อมค่าก่อน/หลัง และเหตุผล
